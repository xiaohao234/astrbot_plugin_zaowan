# astrbot_plugin_zaowan 早晚安打卡

适用于 [AstrBot](https://docs.astrbot.app)（Debian 12 部署）的群聊早晚安打卡插件。
监听群消息即可触发（**无需 @ 机器人**），记录每位群友的早安/晚安时间，
自动统计**睡眠时长**与**清醒时长**，并输出每日排名。数据实时原子落盘，
**重启 AstrBot / 定期重启服务不会丢失任何数据**。

## 功能规则

### 时间窗口
- 早安有效时间：**6:00:00 - 11:59:59**（6 时到 12 时）
- 晚安有效时间：**21:00:00 - 次日 5:59:59**（21 时到第二天早上 6 时）
- 窗口外发送早安/晚安词，会收到提示语
- 排名以**每天上午 6 点整**为界自动清零（凌晨 0-6 点的晚安计入前一晚）
- **重复打卡规则**：距上次成功晚安不足 **6 小时**（可配置）回复提示语，
  不记录不落盘；超过 6 小时且仍在晚安时段内再次晚安，视为一次**新的晚安**
  （适用于半夜醒后再睡的场景，早安配对取最近一次晚安）；同一天重复早安**静默不理会**。
  重复判定同时要求处于同一打卡日（以每天 6 点为界），因此即使把窗口配置调大，
  也不会把第二天晚上的新晚安误判为重复

### 输出效果（与需求样例一致）
| 场景 | 回复 |
| --- | --- |
| 早安（此前无晚安记录） | `@用户 早安～` |
| 早安（昨晚有晚安记录） | `@用户 早安成功！你的睡眠时长为7h10m19s，`<br>`你是今早第1个起床的群友！` |
| 晚安（今日无早安记录） | `@用户 晚安成功！你是今晚第1个睡觉的群友！` |
| 晚安（今日有早安记录） | `@用户 晚安成功！你今天的清醒时长为15h40m16s，`<br>`你是今晚第2个睡觉的群友！` |
| 早安时间不对 | `@用户 现在不能早安哦，可以早安的时间为6时到12时~` |
| 晚安时间不对 | `@用户 现在不能晚安哦，可以晚安的时间为21时到第二天早上6时~` |
| 6 小时内重复晚安 | `@用户 6小时内你已经晚安过了哦~` |
| 同一天重复早安 | （静默不理会，不回复） |

### 触发词（无需 @，整句匹配）
- **早安类**：早安 / 早 / 早上好 / 早好 / 起床(了/啦/咯) / 醒了 / 我醒了 / good morning / gm / morning
- **晚安类**：晚安 / 睡觉(了/啦/咯) / 睡了 / 去睡了 / 去睡觉(了/啦) / 我(去)睡了 / 困死了 / good night / goodnight / gn
- 支持「称呼 + 触发词 + 语气词」组合：如 `大家早安呀~`、`各位晚安啦`、`早!`、`起床咯`、`GM!!`
- 触发词完全自定义（WebUI 插件配置中修改），全部词表见 `_conf_schema.json` 默认值
- 默认**整句匹配**以避免误触（`早饭后吃什么呢`、`晚安故事会` 不会触发）；
  可开启 `fuzzy_match` 模糊匹配（消息包含触发词即触发）

### 时长计算
- **睡眠时长** = 上一次晚安 → 本次早安（仅配对最近 24h 内的晚安，即"昨晚"；
  隔天太久未打卡则只回 `早安～`，窗口大小可配置）
- **清醒时长** = 今日（6 点后）的早安 → 本次晚安
- 格式：`7h10m19s`（小时不补零，分秒补零）

### 查询统计
- 群里发 **`群友作息`**：查询今日早晚安人数
  ```
  今天已经有2位群友早安了，3位群友晚安了~
  ```
- 群里发 **`我的作息`**：查询自己的作息数据（无需 @，自动 @ 回复者）
  ```
  @群友A 你的作息数据如下：
  最近一次早安时间为2026-08-14 08:23:36
  最近一次晚安时间为2026-08-13 23:01:38
  本周早安了2次
  本周晚安了2次
  一共早安了2次
  一共晚安了2次
  一共睡眠了0天17时14分18秒
  ```
  未打卡用户查询显示「暂无记录」与全 0；查询为只读操作，不建档不落盘。
  周统计以**周一 6 点**为界（与打卡日界一致：周日晚的晚安属本周，周一凌晨的晚安属上周），
  跨周后未打卡时查询自动显示本周 0 次。
- 指令 `/sleep_stat` 或 `/早晚安统计`：查看配对次数与平均时长（保留的旧指令）
- 以上触发词均可在 WebUI 配置中自定义（`group_query_words` / `self_query_words`）

## 安装（Debian 12）

**方式一：WebUI 安装（推荐）**
1. 将本文件夹推送到你的 Git 仓库；
2. AstrBot WebUI → 插件管理 → 从仓库安装，填入仓库地址。

**方式二：手动安装**
```bash
# 假设 AstrBot 部署在 /opt/AstrBot
cp -r astrbot_plugin_zaowan /opt/AstrBot/data/plugins/
cd /opt/AstrBot
pip3 install -r data/plugins/astrbot_plugin_zaowan/requirements.txt  # 无第三方依赖，可跳过
systemctl restart astrbot   # 或你的 AstrBot 服务管理方式
```

安装后无需任何配置即可运行；如需调整触发词、时区等，在 WebUI → 插件管理 →
本插件 → 配置 中修改。

## 配置项

| 配置 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| timezone | string | Asia/Shanghai | 时区（IANA 名称），6 点清零与时间窗口按此时区计算 |
| morning_words | text | 见上文 | 早安触发词，逗号分隔 |
| night_words | text | 见上文 | 晚安触发词，逗号分隔 |
| group_query_words | text | 群友作息 | 群作息查询触发词（今日早晚安人数） |
| self_query_words | text | 我的作息 | 个人作息查询触发词 |
| fuzzy_match | bool | false | 模糊匹配开关（包含触发词即触发） |
| dup_night_hours | int | 6 | 重复晚安提示窗口（小时）：距上次成功晚安不足该时长回复「N小时内你已经晚安过了哦~」，设为 0 关闭重复判定 |
| enable_private | bool | false | 是否在私聊中生效（默认仅群聊，排名按群独立） |
| pair_window_hours | int | 24 | 早安睡眠时长的配对窗口（小时） |
| history_cap | int | 30 | 每用户保留的打卡历史条数上限（0 为不保留） |
| prune_days | int | 0 | 清理 N 天未打卡用户（0 = 永不清理，防止数据丢失） |

## 数据存储

- 路径：`<AstrBot>/data/plugin_data/astrbot_plugin_zaowan/records.json`
  （遵循 AstrBot 官方插件存储规范，与插件代码目录分离，**更新/重装插件不丢数据**）
- 结构：`sessions → 群(unified_msg_origin) → 用户 → {早晚安时间戳、累计次数、周计数、封顶历史}`
- 排名不单独存计数器，而是**实时按时间戳统计**当日内打卡人数，
  因此清零逻辑天然正确，不怕计数器与实际状态不同步。
- 周计数通过 `week_start`（本周一 6 点时间戳）+ 周内次数实现，
  跨周后第一次打卡时自动重置（时间戳比较，无后台任务）。
  从旧版本升级时，会自动从保留的打卡历史回填本周计数。

## 安全与健壮性审计

针对三条核心可靠性要求逐项说明：

### 1. 数据不能丢失（定期重启 AstrBot）
- **每次打卡立即落盘**：状态变更与写盘在同一临界区内完成，落盘成功才算打卡完成；
- **原子写入**：`写入临时文件 → fsync → os.replace`，POSIX 原子语义。
  即使进程在写入中途被 kill，`records.json` 也永远是上一个完整版本，绝不会出现半截文件；
- **写盘失败自愈**：若某次写盘失败（如磁盘瞬时故障），内存状态保持正确并记录错误日志，
  下一次打卡会连同未落盘的状态一并写入；
- **损坏自愈**：启动时若发现 records.json 损坏，先将其**改名备份**（`records.json.corrupt-时间戳`）
  再从空状态重建，绝不覆盖原文件，方便人工抢救；
- **卸载兜底**：`terminate()` 钩子最终落盘一次。

### 2. 不能内存泄漏
- **零后台任务**：每日 6 点清零不依赖定时器/线程，而是通过「时间戳 >= 当日 6 点」
  比较实现，不存在定时器句柄、协程或线程的生命周期问题；
- **正则只编译一次**：所有触发词在 `__init__` 编译为 2 个正则对象，之后全部消息复用；
- **内存有上界**：每用户只保存固定字段的最后时间戳 + 封顶历史（默认 30 条）；
  会话/用户/昵称/触发词均有数量与长度上限，异常数据无法撑爆内存；
- **文件句柄**：全部 `with` 语句管理，无泄漏；单实例单锁，无句柄累积。

### 3. 漏洞审查
- **无第三方依赖**：仅 Python 标准库，无 supply-chain 风险；
- **无网络请求 / 无 eval / 无 pickle / 无 shell**：攻击面极小；
- **并发安全**：所有读-改-写与落盘在同一把可重入锁内，多群同时打卡无竞争、无脏写；
- **自消息过滤**：跳过机器人自身消息，杜绝自回复死循环；
- **输入防御**：消息文本先清洗（去表情占位、@ 文本、零宽字符）再整句锚定匹配；
  存入的昵称/ID 均截断限长；
- **数据清洗**：加载时对每个字段做类型/长度/NaN/Inf 校验，被篡改的数据不会进入内存；
- **异常兜底**：每个入口（消息处理、统计查询）都有顶层 try/except，
  任何异常只记日志，插件绝不因单条消息崩溃；
- **边界处理**：负时长钳位为 0、时钟回拨（未来时间戳）防御、6/12/21 点整点边界
  均有明确语义并被测试覆盖。
